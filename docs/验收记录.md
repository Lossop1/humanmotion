## 需求 3　换动作生成模型要能接上（不重写管线）

```
命令  HM_FORCE_BACKEND=mdm python -m hm.main "一个人先向前走，然后转身，最后挥手告别" --job-id acc_mdm --k 4
实际  出口码 1
      A05 强制后端：3 段全部用 mdm
      段/帧     3 段 / 166 帧
      几何      不通过
      语义验证  1 段通过 / 1 段未验证 / 1 段可疑（可疑 002：转身）
判定  部分通过
说明  接口层面成立：一条环境变量切换、无需改代码、产物齐全、契约校验通过；
      质量层面不等价：同一句在 mdm 上几何不通过、转身段被判可疑——这正是默认路由选 momask 的依据。
      「换后端 = 改一行配置」这件事成立，「换后端不掉质量」不成立，不应混为一谈。
```

## 需求 4　大模型负责组织这条管线

```
命令  python -m hm.main "一个人先向前走，然后转身，最后挥手告别" --explain
实际  规划 3 段，提示词分别为
        001 a person walks forward            （可判：disp_m）
        002 a person turns around in place    （可判：yaw_deg/lean_median/backward_m）
        003 a person waves goodbye            （无法判：无校准量）
      结论：2 段可用校准量检查，1 段只能做几何检查
消融  目标树 G51（同一批 30 句，只换规划层）：大模型 30/30 出片 vs 规则兜底 24/30；
      段数 40 vs 30；两者的交界合格率都 100%
判定  通过
说明  「组织」体现在四处，都能在日志里看到：拆段与选词（A02/A06）、按能力表路由（A05）、
      挑候选与交界最优（A12）、合并/截尾/退回/修复（merge_short_segments、repair_junctions）
```

## 需求 5　失败要能说清原因，不能静默给出坏结果

```
命令  python -m hm.main "一个人爬行" --explain
实际  001  60 帧  不支持  无法判（无校准量）  a person crawls forward slowly on hands and knees
      结论  这句话做不了：所有段都属于已知做不出来的动作
命令  python -m hm.main "一个人爬行" --job-id acc_dead --k 4      → 出口码 2，同上原因
命令  python -m hm.main "一个人先躺下，然后向前走" --job-id acc_approx --k 4
实际  semantics.json：001 未验证，detail「原文动作做不出来，已用近似动作代替」
      运行输出：近似代替 1 段 → 出口码 1
判定  通过
说明  三类可区分：做不了（2）／近似代替（1，未验证）／可疑（1）。分镜与字幕角标同步显示 [?]
```
