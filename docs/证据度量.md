# 证据度量

每个数字都由脚本现场算出；改了代码就重跑。命令与判据都写在这里，便于复核。

## 1 可控性执行（朝向 / 地形 / 速度）

### 1.1 方法

```
朝向  取该段首末骨盆的水平位移方向（世界系 atan2(x, z)），把整段绕竖直轴
      旋到「世界前方 + 请求方向」（forward 0° / left +90° / right −90° / backward 180°）。
      世界前方 = 第一段有位移的段的自然行进方向。实现 hm/control.py: enforce_facing
地形  按规划的 terrain.profile（按原段号取值，合并不改序号）把该段整体竖直平移，
      使最低关节落在指定地面高度。实现 apply_terrain
速度  slow/normal/fast → 帧数 ×1.25 / ×1.0 / ×0.8，关节位置线性重采样。
      期望速度 = 原速度 ÷ 因子。实现 apply_speed
```

### 1.2 结果（10 句 / 13 段，`ctrl_01`–`ctrl_10`）

```
朝向   有方向请求的段 10 个：非零修正 2 个（180.0°、18.4°），其余本来方向就对
       修正前偏差 = 后端自发行进方向与请求方向之差（真证据）
       修正后偏差 ≈ 0（按构造，不作为证据）
地形   13 段全部按规划地面高度对齐，垂直修正量最大 0.598 米（台阶段）
       说明：修正量大不是错，而是后端生成的脚高与规划高度不一致，被拉回来了
速度   带速度标注的段 6 个，速度相对误差最大 1.0%（判据要求 ≤20%）
```

### 1.3 已知局限（如实记录）

```
1 朝向的「修正后误差」按定义就是 0——真正有信息量的是「修正前偏差」，
  它同时说明后端对方向词的服从程度（这 10 段里 2 段需要修，最大 180°）
2 ~~合并会丢方向~~ → 已修：合并前检查两段 facing，方向不同且都不是 in_place 时不合并
  实测「向前走，然后向左走」：现在保留 2 段，seg_002 请求 left，修正前 −29.0°、施加 +119.0°
  同时修了上游：规划层对 direction 为 null 的段按中英文关键词兜底推断（向左走 → left）
3 地形只在段首对齐，不作逐帧地面跟踪：台阶中间的高度变化不保证
4 速度用帧数伸缩实现，是全局缩放，不是真正的时间重参数化（起步/落地时刻不变）
```

## 7 判据一致性（E0，用提示词当伪标签）

```
方法  hm/ops/rule_report.py：按动作把多条规则合并成一组（AND），
      在该动作的段上算「漏放」，在其余所有段上算「误报」与特异度
标准集（round26，47 段）
  动作    该动作段  漏放  误报  特异度
  走/跑     18       0    2    93%
  转身       6       0    2    95%
  坐下       1       0    5    89%
  弯腰       3       0    6    86%
  蹲         1       0   10    78%
  跳         3       0    3    93%
  停住       4       0   16    63%   ← 最弱：慢速结尾的段大多被当成「停住」
  踢腿       2       0    2    96%
  出拳       1       0   12    74%
新句集（round1，10 段）
  走/跑 80%｜转身 89%｜弯腰 78%｜跳 78%｜停住 50%｜出拳 67%｜坐下/蹲/踢 100%（该动作段为 0，样本不足）

结论
  1 漏放全为 0：提示词要求做的动作，规则都能通过（说明规则不苛刻）
  2 特异度最差的两个是「停住 63%/50%」与「出拳 74%/67%」——它们是最松的判据，
     也是「可疑」最可能漏掉的地方
  3 这一项是「规则与提示词是否自洽」，不是人工灵敏度；人工那一项在标定包里
```

## 6 复现性（E8）

```
做法  hm/ops/reproduce_check.py：同一句跑两遍（HM_NO_CACHE=1），逐项比对帧数/交界/选中候选/语义/质量指标
未加种子  8 项里 5 项不同（候选选择、交界、穿地、加速度、脚滑都变）
加种子    HM_SEED=1234 → 交界、选中候选、朝向、语义、穿地全部一致；帧数仍不同（144 vs 134），
         加速度比与脚滑仍有小幅差异
为什么还有差  「帧数」来自规划（帧数由大模型给），关掉缓存后规划会重问一次；
            同一句两次规划可能给出不同帧数，进而影响所有下游指标
结论  分两层：
      缓存命中 / 固定规划  → 完全一致（可复现）
      冷跑（无缓存）       → 生成侧已可固定（HM_SEED），规划侧仍可能不同
用法  HM_SEED=1234 python -m hm.main "…" ｜ python -m hm.ops.reproduce_check --sentence "…"
```

## 10 扭曲的真正来源：拟合翻转，不是生成

```
顺着人工标定的那条线索（big_s08 第 12–13 秒）往下挖：
  1 先看候选本身：该段候选的骨骼单帧最大变化只有 23–25 度（平滑）
  2 再看装配后：同一段拟合出来的参数在第 158 帧单帧转动 118 度，骨骼 10/11/16 一起翻
  → 结论：扭曲是「关节 → SMPL 参数」这一步的 IK 翻转，不是生成模型的问题
     （之前一直以为问题在生成侧，这个归因是错的）

试过的修法
  单帧球面插值    修完 118 → 81.7 度，但整帧姿态移动 0.7 米、骨长突变反而更大 → 否证
  换拟合方法      同一句：opt 67.6 度（1 帧 >60）｜ik 22.5 度（0 帧 >30）→ ik 明显更稳

最终采用的兜底（逐段触发）
  拟合完先算该段单帧最大转动；>30 度时用解析 IK 重拟一遍，取更平滑的版本
  实测「先走，然后跑开，最后转身走开」：seg_003 46.7 → 20.5 度，整片最大 123.9 → 32.2 度

## 35 「走回来」是对是错：多义动作先声明再执行（按使用者提的需求改）

### 35.1 使用者的意见

```
「走回来是后退 到底是对还是错 你怎么理解呢？动作本身是可以被解释成回来的
 所以这不是应该纠结的地方 关键是假如用户输入的是走回来 不同场景可能有不同的走回来 怎么识别呢」
```

### 35.2 我的理解（写进设计）

```
1 「走回来」本身不是可判真假的命题，它是一组解释的集合：
   转身往回走 / 后退着回来 / 侧着挪回来（甚至跑回来、被拉着回来）
2 所以系统的问题不是「选错了解释」，而是「默默选了一种、没说」
   之前我们把「慢慢走回来」直接写成 walks backward，字幕写「走」——
   使用者看到「后退」自然判错，而系统也拿不出一条判据说它错在哪
3 正确做法：先声明、再执行、按声明判，并把备选摆出来让人能否决
```

### 35.3 已实现（hm/ambiguity.py）

```
多义表（部分）
  走回来    → 转身往回走 / 后退着回来 / 侧着挪回来
  跑回来    → 转身跑回来 / 倒退着跑
  离开      → 向前走开 / 原路退开
  回到原位  → 转身走回原位 / 后退回原位
  绕一圈    → 绕圈走 / 原地转一圈
机制
  1 规划规则：命中多义词必须在标签里写「理解为：X」，不许默默当成某一种
  2 A06：记录 ambiguous_terms 与 interpretation；没声明就写日志
  3 判定：没声明解释的段一律「未验证」，给不通过也不给假通过
  4 运行报告打印：本次理解为「后退着回来」；也可理解为 转身往回走/侧着挪回来
  5 判定只对「声明的解释」负责（check_interpretation 用该解释的判据）
实测
  「一个人走回来」→ 标签「走回来（理解为：后退着回来）」→ 判通过（与声明一致）
  「快速跑过去，然后慢慢走回来」→ 打印本次理解与两个备选 → 两段均通过
```

## 40 相机原来在逐帧跟人：这是「原地踏步像前进」「地板跟着走」的总根源

```
使用者对 verify3 的标注（第 3 次人工判定）
  clip_01 是后退 ｜clip_02/03/04 空（对）
  clip_05「快跑有楼梯；这里的走、停下像后退」
  clip_06「像站在转盘上，脚凭空在地上转」
  clip_07「还是前进了，但有改善」
  clip_08「跳跃时地板始终在跟着；走是后退」

查到的根因（渲染层，与动作无关）
  hm/render_blender.py 原来每帧把相机放到 root[i] 上方 —— 镜头全程跟着人走。
  后果一：人始终在画面中央，任何位移只能从「地面滑动」看出来 → 被判「还是前进了」
  后果二：地面相对镜头反向滑动 → 被读成「地板在跟着」「像楼梯」
  后果三：脚与地面的接触关系没有稳定参照 → 被读成「站在转盘上转」
修法  相机改为固定机位（用整段轨迹的中位位置），并按轨迹范围扩取景（人不会走出画面）
      顺带修了一个顺序 bug：原来先按未校正距离插关键帧，之后只改当前状态不改关键帧，
      实际渲染用的还是没校正的距离
复验  「原地踏步，然后向前走三步」：镜头不动，前一段人在原地踏步、后一段横向走开
      抽帧图 videos/cam_fix2_strip.png、videos/v6_frames.png
```

### 40.1 这一条为什么重要

```
三次人工判定里，「看不出/像前进/地板跟着」占了一半以上。
它们不是动作做错，而是「镜头跟着人走」让位移无法被看见。
改相机属于呈现层修正；判据与动作都没动，但人判能判到点子上。
```

### 41.2 换脚转身写法：脚不滑了，但经常不转（否证）

          3 绝对量（只用于排序）：路径长度、单帧姿态变化、骨长偏差

          全部在装配层完成，所以换后端不改装配，只改生成与校准数据
```
