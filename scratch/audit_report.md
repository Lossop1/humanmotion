## 二、发现的问题（按严重度）

### 影响可信度（严重）

**问题 1：合并段里“无法判”的子动作被静默放行，导致“通过”名不副实**

- 机制：`hm/run_job.py:587` 与 `hm/guard.py:65` 都是 `if ok is False:` 才算失败；子动作返回 `None`（无校准量）时**既不算失败也不算未验证**。
- 实测：轮20 选中 40 段、其中合并段 22 个，**8 个合并段含无法判子动作却被整段判为通过**，例如
  - `big_s12_r20 seg_001`：[通过] walks forward + [无法判] waves hello with…
  - `big_s25_r20 seg_001`：[通过] walks forward + [无法判] looks to the right
  - `big_s16_r20 seg_001`：[通过] bends forward + [无法判] reaches down / picks up an object
- 直接反例（本轮 A1）：`一个人先向前走，然后挥手告别` → 合并段 prompt=`a person walks forward and waves goodbye`；选中候选签名 **手腕高于肩 −0.378 米、位移 1.19 米**（即没有挥手），但报告写「语义验证 1/1 段通过校准量」，分镜标 `[OK]`。
- 影响：文档与报告里的「可疑 0」「合并段动作缺失 0/20」「语义验证 N/M 通过」**不能作为“动作真的做出来了”的证据**。

**问题 2：不支持的动作用近似动作替换后合并，整句报成功（出口码 0）**

- 实测：`一个人先躺下，然后向前走` → A03 已判 `seg_001=unsupported`；最终只有 1 段，prompt=`a person sits down in place and walks forward`，`action='近似：躺下'`、`support_status=unverified`，分镜标 `[OK]`，`去掉的段 无`，出口码 **0**。
- 机制：合并时把新段重置为 `support_status="unverified"`（`hm/run_job.py:552-553`），于是 A07 不再跳过，生成照做。
- 影响：对使用者而言“躺下”变成了“坐下并向前走”，系统却报告成功；这与你对外宣称的“做不出来的动作会被拦下并如实报告”不一致（单句 `一个人爬行` 确实报 2，但多动作句会被替换）。近似本身在 label 里写了，属于透明，但**出口码与“无丢段”给出的印象是“全部做到了”**。

**问题 3：部署记录过期**

- `MIRROR.txt` 记 `aac8a7c`，本地/远端代码实际对应 `e0b02bf`（抽查 15 个文件哈希一致）；远端 git HEAD 停留在 `1c67901`。
- 影响：任何“远端跑的就是仓库这份代码”的判断，目前只能靠逐个哈希比对，不能靠记录。`tools/sync_remote.sh` 存在但未被（本地）再执行过一次。

### 轻微

**问题 4：出口码 1 的定义在实践中没有覆盖**
- 文档说 `1 = 出片但有段被去掉`；我构造 `一个人先躺下，然后向前走` 想触发它，结果是被替换+合并后出口码 0（问题 2）。A1/A2 只验证了 0 与 2。

**问题 5：storyboard 时长与成片帧数不一致**
- `outputs/audit_e2e/storyboard.json` 的 `duration_frames=95`，成片 92 帧（截尾 3 帧），报告里没有体现这 3 帧的截断。

**问题 6：目标树内部状态不一致**
- `现状` 表第 43 行 `G2 部分 …`，而 `### G2 …【未达成】`（章节标题未同步更新）。

**问题 7：测试汇总行缺失**
- `pytest tests` 只有点阵，没有 `154 passed` 汇总行（本地配置/插件所致），审核只能按点数判断；CI 里若不解析退出码以外的信息，会看不出通过数。

## 三、一句话总评

**作为毕业设计的功能交付：可以交。** 一句中文能端到端出片（4 件产物、出口码语义可用、批量和三种说明命令都work），质量闸门（守门七项、自检、154 个单测）真实有效，五臂消融与换后端演练都能复现。

**但“语义已验证/可疑 0”这一层结论目前不成立**：合并段对无法判的子动作静默放行（8/22 段），并且不支持的动作用近似动作替换后仍以出口码 0 报成功。答辩若被追问“你怎么知道视频演的就是那句话”，现有数字答不上来。建议在交付前把报告口径改成“可判的量通过；未判子动作单列不计入通过”，并让 `[OK]` 只出现在子动作全部可判且通过时。
